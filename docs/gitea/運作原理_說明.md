> 這份是給「非工程背景」的 owner 看的：Gitea 到底怎麼跑、資料存在哪。
> 本文件是 2026-07-27 當場把服務跑起來、連資料庫實際查過之後寫的，數字都是真的，不是抄舊文件。
> 這套 Gitea 完全沒被改過核心，照原本方式運作；本機同時還跑著 MaintVault（埠 5000），兩者各跑各的、互不干擾。

## 實際發生的事（一步一步）

1. 你手機/電腦開瀏覽器，打 `http://<PRIVATE_IP>:3000`
2. 請求送到 Gitea 程式（它監聽埠 3000，背後有 systemd 盯著，掛掉會自動重啟）
3. Gitea 要確認「你是誰、有沒有權限」→ 去問 PostgreSQL 的 gitea 庫（讀 user 表）
4. Gitea 要顯示某個倉庫的程式 → 去讀 `repos/` 裡的檔案
5. 你 push 一段程式上去 → Gitea 把程式碼寫進 `repos/`；你改了設定/新增帳號 → Gitea 寫進 PostgreSQL

## 關鍵觀念：兩種資料分開放

- 「帳號、密碼、權限、倉庫設定」→ 放在 PostgreSQL 的 `gitea` 庫（public schema）
- 「程式碼本身（真正的檔案）」→ 放在 `repos/` 資料夾，不在資料庫
- 兩個是分開的，缺一不可

## 為什麼「檔案」要放資料夾、不塞進資料庫？

這是最常被問的問題。先說結論：**資料庫當然可以存檔案，但 Gitea 故意不把檔案本體塞進資料庫，只把「整理的資訊」放資料庫。這是設計選擇，不是「非放資料夾不可」。**（MaintVault 也是同樣邏輯，詳見 maintvault/運作原理_說明.md）

兩種資料要分開看：

| 類型 | 例子 | 放哪 |
|------|------|------|
| ① 結構化小資料（資料庫擅長） | 帳號、密碼、權限、誰上傳的、什麼時候、倉庫設定 | PostgreSQL（gitea 庫的 public schema） |
| ② 檔案本體（大塊資料，資料庫不擅長） | 程式碼幾百 MB | 硬碟資料夾（repos/） |

為什麼 ② 故意放資料夾：

1. 檔案可能很大（幾百 MB 的程式），全塞進資料庫會讓資料庫變超肥、查詢變慢、備份也難。
2. Git 這套東西「本身就是一個檔案版的資料庫」——它用自己的方式（按內容算亂數編號）把每個版本管得很好。再把整套塞進 PostgreSQL 是多此一舉。
3. 瀏覽器要下載一個檔案時，直接從硬碟讀比「從資料庫撈出來再傳」快很多。
4. 資料庫強項是「常常要搜尋/比對的小資料」（例如查某個帳號、找某個倉庫的設定、列誰有權限），不是裝大檔。

**正確理解：不是二選一，是合作。**
- 資料庫 = 名冊 + 設定（誰、權限、哪個倉庫、倉庫設定）
- 資料夾 = 真正的程式碼本體

你在 Gitea 上找某個倉庫，資料庫幫你找到「這個倉庫的設定和權限」，然後程式去 repos/ 資料夾把程式碼本體讀出來顯示給你。兩邊一起運作。

（註：如果你硬要把整個檔案塞進資料庫也做得到，用 BYTEA 欄位即可。但對這類「檔案本體要存要取」的需求，現在「資料夾存檔 + 資料庫存資訊」是最穩、最快、最好備份的做法。）

## 實際資料位置一覽

- 平台資料（誰、權限、設定）→ PostgreSQL 的 `gitea` 庫（public schema，磁碟在 `/var/lib/postgresql/16/main`）
- 程式碼檔案（倉庫內容）→ `/opt/gitea-standalone/repos/`
- 舊的 `gitea.db` → 遷移前的 SQLite 備份（約 2MB，最後修改 2026-07-24，之後沒再動），已不被使用。可留作回退或刪除，但刪除前請先確認 PostgreSQL 裡的 gitea 庫資料完整。

## 與 MaintVault 的差別（你之前在意「不要像 GitHub」）

- Gitea：Git 平台，有 repo / issue / pull request，介面像 GitHub。資料在 PostgreSQL 的 `gitea` 庫（public schema）。
- MaintVault：純上傳/列表/搜尋/下載，沒有那些術語，介面就是資料櫃。資料在同樣的 PostgreSQL，但放在獨立的 `vault` schema，跟 Gitea 的 public schema 不打架。
- 兩者都用同一個 PostgreSQL 實例（127.0.0.1:5432），只是「資料庫內的歸檔方式不同」：Gitea 用預設的 public schema，MaintVault 用自己開的 vault schema，表名也不會重複，所以同庫共存沒問題。

## 常用操作（給 owner 備查）

- 看服務有沒有在跑：`systemctl --user status gitea`
- 重啟服務：`systemctl --user restart gitea`
- 看即時日誌：`journalctl --user -u gitea -f`
- 網頁打不開時，先確認服務是 active、且這台機器 IP 還是 <PRIVATE_IP>
- 備份要兩邊都做：① `pg_dump gitea` 匯出資料庫；② 整個 `repos/` 資料夾壓起來。只備一邊都不算完整。
