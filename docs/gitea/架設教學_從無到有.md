# Gitea 地端小團隊 Git 平台 — 從無到有完整教學

> 適用對象：公司小團隊 demo，跑在自己的 Linux VM 上（地端部署），區網內用手機/電腦開瀏覽器就能用。
> 本篇是「怎麼從一台空機器搞到現在這個資料夾」的逐步紀錄，每一個檔案、每一個設定都解釋為什麼那樣寫。

---

## 第 0 步：先搞懂我們在做什麼（概念）

你要的是「公司小團隊 Git 平台」，放在自己機器上（地端部署），不給外面網路用。

- Git 本身只是版本控制工具；要讓一群人透過網頁 push/pull、開帳號、看儀表板，需要一個「Git 平台」軟體。
- 常見選擇：GitHub（雲端）、GitLab（大、重）、Gitea（輕量、適合小團隊）。本 demo 選 Gitea，對小團隊是正確的。

Gitea 有兩種跑法：

1. 直接跑一個執行檔（binary），最省事 → 本 demo 用這個。
2. 用 Docker 跑（Gitea + 獨立資料庫）→ `docs/` 留了一份「上公司雲」的範本，以後再說。

這個 demo 的目標：區網內用手機/電腦開瀏覽器就能用，VM 重開機會自己起來。

---

## 第 1 步：準備一台 Linux 機器

- 一台 VM（本機 hostname 叫 `gitea-server`，使用者 `gitea`，區網 IP `<PRIVATE_IP>`）。
- Gitea 需要 `git` 指令，機器要先裝 git（本機是 2.43.0，OK）。
- 你不是 root，是一般使用者 `gitea`，所以服務用「systemd user service」（使用者層級），不是系統層級。這影響後面 `gitea.service` 的擺放位置。

---

## 第 2 步：把 Gitea 執行檔拿下來

- 去 Gitea 官網下載對應 CPU 架構的單一執行檔，放到 `~/gitea-standalone/gitea`。
- 它「就是一個檔案」，不用安裝、不用編譯。記得給執行權限（`chmod +x gitea`）。
- 執行檔內建 SQLite 支援（啟動訊息裡有寫 `sqlite, sqlite_unlock_notify`），這就是為什麼「不用另外裝資料庫」也能跑。

---

## 第 3 步：寫設定檔 app.ini（核心，逐行講）

Gitea 第一次跑本來會開「安裝網頁」讓你填設定；為了可複製、可備份，我們直接寫好 `app.ini`。逐行說明：

### 基本
- `APP_NAME = 公司小團隊 Git 平台 (demo)` → 網頁標題、左上角名字，隨便取。
- `RUN_USER = wsfoo` → 用哪個系統帳號跑 Gitea。必須是實際存在的帳號，且對 `gitea.db` / `repos` 有讀寫權限。填錯會起不來。
- `RUN_MODE = prod` → 正式模式（錯誤訊息較簡潔、效能較好）。開發才用 dev。
- `WORK_PATH = /opt/gitea-standalone` → Gitea 工作根目錄。它找 app.ini、gitea.db、repos、log 都從這裡算相對路徑。整個資料夾搬走時，這行要跟著路徑改。

### [security]
- `INSTALL_LOCK = true` → 關鍵！表示「已經安裝過了，不要再開安裝網頁」。第一次正常跑完 Gitea 會自己設成 true。想重來就設 false 並清掉 db。
- `SECRET_KEY=***` → 加密 cookie / session 的鑰匙，要夠亂。搬家要一起帶走，否則舊登入狀態全部失效。
- `INTERNAL_TOKEN=***` → Gitea 內部元件之間溝通用的 token。搬家也要帶走。

### [service]
- `DISABLE_REGISTRATION = true` → 關閉「任何人都能自己註冊」。小團隊 demo 不希望陌生人亂建帳號，帳號由 admin 用指令加（manage.sh adduser）。

### [server]
- `PROTOCOL = http` → 用 HTTP（沒加密）。區網 demo 沒掛憑證。要對外或要加密才升級 https。
- `HTTP_ADDR = 0.0.0.0` → 監聽「所有網卡」。只想本機用就填 `127.0.0.1`；填 `0.0.0.0` 代表區網內其他電腦/手機也能連。
- `HTTP_PORT = 3000` → 網頁走 3000 埠。所以網址是 `:3000`。
- `DOMAIN = <PRIVATE_IP>` / `ROOT_URL = http://<PRIVATE_IP>:3000/` → 決定「產生出來的倉庫網址長怎樣」。同事 clone 看到的 URL 就是這裡。用 IP 不用名字（要用名字得額外架 DNS / hosts，demo 先用 IP 最穩）。
- `SSH_DOMAIN = <PRIVATE_IP>` → 用 SSH 方式 clone（git@...:...）走這個網址。
- `START_SSH_SERVER = false` → Gitea 自己不內建 SSH 伺服器。同事要用 SSH 走系統本來的 sshd。

### [database]
- `DB_TYPE = sqlite3` / `PATH = gitea.db` → 資料庫用 SQLite，檔案叫 `gitea.db`（放在 WORK_PATH 下）。

### [repository]
- `ROOT = /opt/gitea-standalone/repos` → 所有 Git 倉庫實際檔案放在哪。注意：倉庫內容存在這裡，不是存在 `gitea.db`（db 只存帳號/設定/issue 等「平台資料」）。

### [log]
- `MODE = file` / `LEVEL = Info` / `ROOT_PATH = /opt/gitea-standalone/log` → 日誌寫成檔案、層級 Info、放在 log/。出問題看這裡。

### [oauth2]
- `JWT_SECRET=***` → 以後接第三方登入（Google 等）用的密鑰。demo 沒用，搬家也要帶走。

## 第 4 步：第一次啟動，讓它「安裝鎖定」

直接 `./gitea web -c app.ini` 前台跑一次，它讀到設定、建好 `gitea.db`、把 `INSTALL_LOCK` 設 true，就可以 Ctrl+C 關掉。
（本機 `INSTALL_LOCK` 已經是 true，表示這步早就做過了。）

---

## 第 5 步：包成開機自啟的服務（gitea.service）

每次手動跑指令很麻煩，且 VM 重開就沒了，所以註冊成 systemd 服務。`gitea.service` 內容：

```
[Unit]
Description=Gitea (公司小團隊 Git 平台 demo)
After=network.target          # 等網路起來之後再啟動

[Service]
WorkingDirectory=/opt/gitea-standalone
ExecStart=/opt/gitea-standalone/gitea web -c /opt/gitea-standalone/app.ini
Restart=always                # 掛掉 5 秒後自動重啟
RestartSec=5
Environment=GITEA_WORK_DIR=/opt/gitea-standalone

[Install]
WantedBy=default.target       # 使用者登入後啟動（user service 寫法）
```

- 檔案放在 `~/.config/systemd/user/gitea.service`（使用者層級，不是 `/etc/systemd/system`，因為不是 root）。
- 啟用（只用做一次）：`systemctl --user enable --now gitea.service`
  - `enable` = 開機自啟；`--now` = 現在就啟動。
- 小坑：user service 預設「使用者登出就會被砍」。要開 linger（`loginctl enable-linger wsfoo`）讓登出 SSH 後服務繼續跑。本機已處理好。

---

## 第 6 步：寫一個管理小抄 manage.sh

包裝常用指令，不用每次背 systemctl：

- `status`  → `systemctl --user is-active gitea.service`（看在不在跑）
- `start` / `stop` / `restart` → 對應 systemctl 指令
- `log`     → `journalctl --user -u gitea.service -f`（即時看日誌）
- `adduser 使用者 密碼` → 呼叫 `./gitea admin user create ...` 在資料庫加帳號

用法：`bash manage.sh status`

---

## 第 7 步：加帳號、建倉庫

- 因為第 3 步關掉自由註冊，加同事用：`bash manage.sh adduser 同事名 密碼`（預設密碼沒給是 `ChangeMe123`，記得改）。
- 倉庫：同事登入網頁後，點右上角「+」就能自己開新倉庫，不用命令行。
- 本機 `repos/admin/` 下已有 `git.git` 和 `demo-project.git` 兩個示範倉庫。

---

## 第 8 步：備份與搬家（SQLite 的好處在這）

因為是 SQLite + 單一資料夾，備份超簡單：

1. `bash manage.sh stop`（先停，避免寫一半）
2. `tar czf gitea-backup.tar.gz -C ~ gitea-standalone`（整包壓起來）
3. 搬去新機器：解開 → 改 app.ini 裡的 IP/路徑 → 重新 enable 服務。

重點：`gitea.db`（平台資料）+ `repos/`（程式檔案）兩個都要帶走，缺一不可。

---

## 第 10 步：安全提醒

- admin 密碼還是預設 `<CHANGE_ME>`，要登入後立刻改。
- `.secret_key` / `.internal_token` / app.ini 裡的密鑰別外洩（壓縮備份檔要傳給別人前先想清楚）。
- 現在是 HTTP 沒加密，只適合區網 demo；要對外或放真實公司資料，得升級 HTTPS + 考慮 PostgreSQL。
