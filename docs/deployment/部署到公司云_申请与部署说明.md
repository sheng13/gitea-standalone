# 将「公司小团队 Git 平台 (Gitea)」部署到公司云端的申请与部署说明

> 用途：给 IT / 云平台管理员 / 主管看，说明我们要做什么、要什么资源、怎么部署、怎么过合规。

## 一、背景（为什么需要）
- 我们小团队已在本机 VM (wsfoo) 用 Gitea 跑通一套自建 Git 平台，验证了对代码托管/协作的真实需求。
- 现需要扩展到全公司使用，要求：全公司可达、传输加密、高并发、自动备份、接公司统一账号。
- 代码涉及服务器维修等敏感资料，依资安规范必须私有部署，不可使用外部托管 (GitHub/Gitee)。

## 二、技术选型
- 软件：Gitea 1.23.x（开源、免费、轻量，已实测可用）
- 数据库：PostgreSQL（高并发读写，替代 demo 用的 SQLite）
- 部署形态：单机或容器 (Docker/K8s)，依贵司云环境而定
- 访问：公司内网 DNS 名称 + HTTPS（如 git.公司网域.com）
- 账号：对接公司 LDAP / SSO，免除手动建账号

## 三、需要的云资源（最小可用 / 推荐）
- 最小（小团队~几百人）：2 vCPU / 4 GB RAM / 50 GB 磁盘，Linux
- 推荐（上千人）：4 vCPU / 8 GB RAM 起，PostgreSQL 独立实例，磁盘按代码量估
- 网络：开放 443 (HTTPS)，DNS 一条 A 记录指向该机器
- 备份：云快照或定时备份 ~/gitea-standalone 等价目录 + 数据库 dump

## 四、部署步骤（管理员执行）
1. 云上开 Linux VM，安装 Docker 或直接使用 Gitea 执行档。
2. 将现有 ~/gitea-standalone/ 整目录迁移（或全新安装后导入 repo）。
3. 修改 app.ini：ROOT_URL 改为 https://git.公司网域.com/，数据库改 PostgreSQL。
4. 启动服务（systemd / docker compose），设开机自启。
5. IT 加 DNS 记录 + 申请 HTTPS 证书（Let's Encrypt 或公司 CA）。
6. 配置 LDAP/SSO 登录。
7. 设自动备份（每日 dump + 异地复制）。

## 五、合规要点（半导体/资安相关）
- 全程私有部署，代码不出公司网络。
- 传输 HTTPS 加密，存储可加密磁盘。
- 访问权限按组织/专案控管，操作有审计日志。
- 定期备份，防资料蒸发。

## 六、我们已准备好的资产（可移交 IT）
- ~/gitea-standalone/ ：完整平台目录（程式+设定+数据库+repo）
- README_说明.md ：结构/备份/搬家步骤
- 本文件：部署说明

6. 资安合规有哪些硬性检查要先过？
